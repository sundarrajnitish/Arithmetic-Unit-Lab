Digital system design · FPGA arithmetic

An arithmetic unit, built up from full adders.

P = A·B/4 + 1A·B/2C + DA·B/C² + D

Two 8-bit operands go into registers, a multiplier forms the product, a shifter divides it and an adder finishes the formula, all in structural VHDL. On top of the base formula it takes any operand width, signed numbers, two division formulas and serial I/O, and has a speed-optimised build. Every result on this page is checked against the same reference model as the testbenches.

Multiplier explorer

Where the partial products go

An N×N multiply is N² one-bit products added in the right columns. The carry-save array adds them row by row; the Dadda tree squeezes every column at once with full and half adders until two rows remain. Both handle signed operands with the Baugh-Wooley trick: complement the bits that touch exactly one sign bit and add 2N + 22N−1.

Division

Two ways to divide, one rounding rule

Dividing by 2C is a shift; dividing by C² needs a real divider. Both round toward zero, the rule VHDL, C and Python use for integers. A plain arithmetic shift rounds negative numbers down instead, so the shifter reports whether it dropped any 1s from a negative number and the final adder adds that bit through its carry-in. No extra adder needed.

Serial I/O

Fifty-six pins become eight

The parallel unit needs 56 pins: clock, reset and load, 34 input bits (A, B, C, D, sgn, fsel) and 19 outputs (P, status, err, ovf). arith_unit_serial shifts the same fields in one bit per clock, pulses start, and shifts P, err and ovf back out. Synthesis

Area and speed, measured

Each multiplier sits between input and output registers and goes through yosys and nextpnr for a Lattice iCE40 HX8K, three placement seeds each. The gate depth counts logic gates on the longest path as the VHDL writes them, before the tool restructures anything. A structural prefix adder shortens that depth a lot, but on a LUT FPGA the dedicated carry chain wins: the fastest build pairs the Dadda tree with an inferred final adder.

Design notes

The decisions behind the datapath

A handful of choices shape everything above: how operands enter, how signs and rounding cost no extra hardware, where the one multiplier is reused, and which adder each target gets. Each note names the part of the RTL that carries it out.

Method

From specification to bitstream

Everything runs on open tools: GHDL for simulation, yosys with the GHDL plugin and nextpnr for synthesis, Python and Node for the models. The RTL is plain VHDL-93, so ModelSim and Quartus take it as well; a Quartus project for the course's MAX 10 board is in syn/quartus.

Specify

Golden model

model/au_model.py defines P, err, ovf and the latency for every input, plus the Dadda plan.

Design

Structural RTL

Full adders, half adders, partial-product and prefix cells, registers. Generics pick N, C and D widths and architectures.

Verify

GHDL testbenches

Exhaustive where possible, model vectors elsewhere, driven through the real load/status handshake.

Measure

yosys + nextpnr

LUTs, flip-flops, fmax and as-written gate depth for every architecture and width.
